# 验证瓶颈：生成式 AI 时代的定位锚点（2026-09-21）

> 事实锚定文档。所有数字都标了一手/二手来源，可直接被页面与提案引用。
> 本文**不**是竞品对比表——它是回答一个问题：**为什么「验证」而不是「生成」
> 是这个时点的稀缺品。**

---

## 一、RayGun（杜克大学，Nature 2026-07-29）

**来源等级：一手**（arXiv/DOI 原文直读 + Duke 医学院新闻稿）

- DOI: `10.1038/s41586-026-10842-8`，Published online 2026-07-29
- 作者：Kapil Devkota, Daichi Shonai, Joey Mao, Young Su Ko, Wei Wang,
  Scott Soderling, Rohit Singh（杜克大学医学院）
- 代码：`github.com/rohitsinghlab/raygun`
- 技术栈：ESM-2 蛋白语言模型 → 分块平均（K=50）→ 固定维度高斯分布
  → Transformer 编码器/解码器 → 解码回序列。**单步生成**，非扩散迭代。

### 关键数字（一手）

| 项目 | 数值 |
|---|---|
| 缩放能力 | 缩短 10–25%（有时 >50%），也可扩容 |
| 控制参数 | **2 个**：噪声强度（序列修改幅度）+ 目标长度 |
| 生成速度 | A100 单序列 ~0.3 秒（论文报告约比扩散模型快 100 倍） |
| 候选规模 | 荧光蛋白 7 万候选 / TurboID 50 万候选 / EGF 1 万候选 |
| **实际湿实验验证** | 荧光蛋白 8 个（6 个发光）/ TurboID 11 个（6 个表达）/ EGF 2 个 |
| 结构指标 | ±10% 内 TM-score ≥ 0.78；mTOR 缩短 20% 仍 ~0.70 |
| 功能指标 | 最优 EGF 变体 Kd = 0.274 μM（野生型 0.759 μM，~2.8 倍） |
| 自认局限 | 缩短超 50% 功能保留率显著下降；人工进化出的超天然活性（TurboID）计算设计难完全复刻 |

## 二、本文档要引用的核心数字

### 验证覆盖率 = 实验验证数 ÷ 生成候选数

```
TurboID   : 11 / 500,000 = 2.2×10⁻⁵
荧光蛋白   :  8 /  70,000 = 1.1×10⁻⁴
EGF       :  2 /  10,000 = 2.0×10⁻⁴
```

**即：生成式 AI 产出的候选，实际接受湿实验验证的比例在万分之一量级。**

这是 2026 年 7 月 Nature 上一篇同行评审论文里、由作者本人实测出来的数字。
不是推测，不是行业估计。

### 为什么这个数字重要

论文本身没有把它当成问题——作者的目标是证明「方法可行」，只需要少量候选
成功就够了。但对整个领域的实际运转来说：

1. **生成成本已趋近于零**：单步 0.3 秒，50 万候选在单机上可批量产出。
2. **验证成本没有跟着下降**：表达 → 纯化 → 活性测定 → 结构表征，每个候选
   都是天级到周级的人力与试剂成本。
3. **两者之间出现了一个数量级的缺口**：10⁵ 量级候选 vs 10¹ 量级验证。
   这不是「验证还不够快」，是**结构性的验证瓶颈**。

CASRAI 那篇同行评论（二手，2026-07，`casrai.org/news/raygun-generative-protein-miniaturisation-esm2-validation-gap-2026`）
把这一点单独拎出来作为标题级论断，且明确指出这是**整个生成式蛋白设计领域的
共性局限**，不是这篇论文独有的问题。

## 三、对我方定位的含义

### 我方不是「更好的生成器」

RayGun 这类系统的能力面（序列生成、长度改造、固定维度表示）与我方
（GP 代理 + UQ + 门禁裁决）**完全不交集**。试图在生成能力上竞争是
错误方向：生成式 AI 的边际成本正在快速趋零，谁做谁亏。

### 我方位置 = 瓶颈本身

我方定位是**「可信验证层」**：替代真实实验、诚实 UQ、可归档 V&V。
RayGun 的数据恰好是这个定位最有力的外部证据——**当生成变得几乎免费，
「判断哪个候选值得进实验」变成最贵的环节**。

### 可引用的对外表述（已核实版本）

> 2026 年 7 月杜克大学在 Nature 发表的 RayGun 可生成 50 万个蛋白候选，
> 其中 11 个接受了湿实验验证——验证覆盖率 2.2×10⁻⁵。生成式 AI 让
> 「造一个候选」变成免费操作，验证正成为整个领域的结构性瓶颈。
> SwarmLabs 做的正是这一层：82 个场景 / 79 PASS 的独立验证账本，
> 每个裁决可追溯到文献参数与量纲检查。

### 我方与生成器的分工（互补而非竞争）

| | RayGun 类生成器 | SwarmLabs |
|---|---|---|
| 回答的问题 | 「可能是什么？」 | 「这个能用吗？」 |
| 输出 | 海量候选序列 | 单一裁决 + 误差条 + 理由 |
| 成本曲线 | 趋零（0.3 秒/候选） | 与候选数无关（按场景计费） |
| 失败模式 | 候选无效（无信息量） | 裁决错误（有信息量，可追责） |
| 验证方式 | 作者自测（湿实验） | 文献区间 + 湿实验锚定 + 独立复算 |

### 关键区分（避免自我指涉）

生成器的成功率数字**由作者自报**：8 个候选中 6 个发光、11 个中 6 个表达——
这是作者挑了哪几个送检、怎么挑的，全部取决于作者的选择。

我方门禁裁决**不由我方选择**：账本是离线重建、字节指纹可复算、
5 个 REFUTED 案例被保留并硬阻断（不美化）。**「不删坏结果」才是
可信验证层的实质**——这是生成器类系统结构上做不到的事。

## 四、RayGun 的技术对我方无提升

明确记录（避免后续重复评估）：

| 维度 | RayGun | 我方 | 结论 |
|---|---|---|---|
| 计算栈 | ESM-2 权重 + GPU + Transformer | 纯 numpy + 纯 stdlib | 移植 = 买 GPU + 下权重 = 违反自治红线 |
| 输入 | 蛋白序列（离散、变长） | 连续物理输入 | 无共同抽象 |
| 训练 | 海量序列预训练 | 无训练，解析/代理建模 | 技术路线不同源 |
| 评估 | TM-score / Kd / 发光 | R² / 覆盖率 / 锚定 | 指标不通用 |

**结论：无技术可移植。仅战略叙事价值。**

  的差异化路径叙事。
