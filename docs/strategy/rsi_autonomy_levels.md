# SwarmLabs 自主权分级（对齐 Theseus Labs RSI L1–L5）

**背景**：Theseus Labs 联合上交/清华/字节 发布 RSI 五级自主权框架（arxiv 2609.11873, 2026-09-14），基于 72 家工业证据提出「AI 系统应如何分级评估自主权」。SwarmLabs 借这一公开框架给**自己打分**，并把每一档升级路径写清楚——**这不是营销话术，是投资人/独立审计可以直接对照的自评**。

## 五级定义（Theseus 原始口径）

| 级别 | 中文名 | 核心语义 | 典型代表 |
|---|---|---|---|
| **L1** | 执行自主 | 人类设计任务，AI 执行；无策略自主、无经验获取、无递归改进 | ChatGPT 单次对话、Claude 单次工具调用 |
| **L2** | 策略自主 | AI 自主决定**怎么做**（工具选择、路径规划），但仍由人类决定**做什么** | Claude Code、Cursor Composer、Devin |
| **L3** | 经验获取自主 | AI 在任务之间**累积经验**（记忆、技能、偏好），下次做得更好 | 长期记忆 + 技能库（EverOS 类） |
| **L4** | 环境适应自主 | AI 从部署环境的**真实反馈**（用户行为、指标）中自我调整 | Google Search 排序、推荐系统 |
| **L5** | 递归继承自主 | AI 改进**改进机制本身**——AI 优化自己的优化器、自己写自己的评测 | Theseus Labs 自述目标、GPT-6 Astra 部分场景 |

## SwarmLabs 当前评估：**L1 稳固、部分组件已达 L2、少量组件触碰 L3**

诚实打分——按子系统而不是按整体给一个数：

| 子系统 | 当前级别 | 证据 | 未达更高档的阻塞 |
|---|---|---|---|
| `paper_validation_loop.py` | **L1** | 14 篇论文 × 18 基准，脚本按硬编码清单跑，人决定改哪篇 | 没有让 AI 决定「下一篇该跑哪篇」 |
| `verification_gate.py` | **L1** | 阈值硬编码，PASS/REFUTED 按公式判定 | 阈值不自主演化 |
| `engine/flywheel.py` | **L1** | 每日跑固定 7 步，人写脚本 | 步骤顺序/新步骤由人加 |
| `geo_engine.py` + 博客生成 | **L1 → L2 边界** | 14 篇博客按模板生成，但模板选择/关键词是脚本内的 if/else 而非 AI 决策 | 内容创意仍由人 |
| MCP `swarmlabs_vv_server.py` | **L1** | 7 tools 硬编码 | 工具集不自主扩展 |
| `scripts/gh_push.py` + CI 门禁 | **L1** | 走固定 Contents API | 无自主重试策略 |
| 飞轮自动化 `1786267221077` | **L1** | 每日定点跑一次 | 无自我调度 |
| `wet_lab_anchors.py` 拟合反推 | **L2 局部** | 对 10 个可锚定场景自动拟合 μmax/Ks/m_s | 只在预定义 6 锚点上运行 |
| `scenario_library_density.py`（2026-09-16） | **L2 局部** | 自动投影场景库到主参数轴并出密度热图 | 投影轴由人定义 |
| 47,566 实体库 | **L1 → L3 边界** | 数据每日扩充，但未用于驱动决策 | 没有实体→决策的反向回路 |
| `docs/strategy/` 战略文档 | **L1** | 人写 | 无 |
| 本 RSI 自评 | **L1** | 人写 | 无 |

**综合口径**：SwarmLabs 主体 = **L1**，若干分析模块已局部触及 **L2**；尚未系统性抵达 **L3**（长期记忆 + 经验累积）。

## 升 L2 的具体路径（下一季目标）

从 L1 → L2 不是「加个 LLM」，是**把「做什么」的选择权从人手里挪一点到 AI 手里**，且每一步都保留人类 checkpoint（`verification_gate.assert_action_allowed` 是那道 checkpoint）。

| 目标 | 具体动作 | 验收指标 | 依赖 |
|---|---|---|---|
| AI 选下一个待验证场景 | 让 agent 从 117 PENDING engines 里按 gap 严重度+数据可获取性挑 1 个 | 每次自动选出的场景，人工审阅通过率 ≥ 60% | 需要 `scenario_library_density.py` 的密度图作为输入 |
| AI 选下一批实体扩展领域 | 从 `domains.py` PENDING 7 桶里自动挑选 1 桶启动 | 3 个月内至少 2 桶从「0 场景」变「≥1 场景」 | 需要 entity_store 反查能力 |
| AI 决定博客更新优先级 | 让 AI 从 14 篇博客里挑 3 篇优先更新（依 GEO 健康度 + 引用次数） | 优先更新的 3 篇 GEO 引用量提升 ≥ 20% | 需要 `geo_engine --probe` 输出作为输入 |

**这些目标刻意选在「AI 做选择、人类决定范围」这一档**，不追求让 AI 决定「做什么」。这也呼应 `verification_gate` 的哲学：AI 可以在授权范围内选择，但硬闸门仍在。

## 升 L3 的具体路径（半年目标）

L3 的核心是**跨任务记忆 + 经验复用**。SwarmLabs 已有 47,566 实体但未被反查利用——这是最直接的抓手。

| 目标 | 具体动作 | 依赖 |
|---|---|---|
| 实体→场景反向索引 | 建 `data/entity_to_scenario.json`：每条实体记录关联到 1-3 个相关场景 | 需先给 62 场景打语义标签 |
| AI 用实体记忆做 gap 预判 | 新场景加入前，先查 47k 实体库是否已有相关证据 | 反向索引 |
| 飞轮每日决策留痕 | 每次 AI 选择的场景/领域/博客都写入 `data/ai_decisions.jsonl` | 无 |

## 升 L4 的具体路径（远期，需要产品化）

L4 需要**真实用户反馈闭环**。当前 SwarmLabs 的付费用户量接近 0（Pro ¥39.9、终身 ¥199 已上架但未商业化），L4 无从谈起。诚实说法：**L4 不是技术目标，是商业化目标**——先把 license.swarmlabs.tools 跑通月流水，再谈 L4。

## L5 与本项目关系

L5（递归继承自主）目前是**研究话题，不是产品目标**。SwarmLabs 的定位是「科研验证基础设施」，而不是「自我改进的 AI 系统」。SoL-Pi（NVIDIA 2026-09-11）已经在 L5 边界做了初步实验（AI 优化 harness 自己），可作为**观察对象**，不作为 SwarmLabs 路线图上的节点。

## 一句话总结

> SwarmLabs 目前是 L1 稳固、局部触 L2、少量触 L3 边界的科研验证基础设施；升 L2 靠「把选择权从人挪一点到 AI，但硬闸门仍在」；升 L3 靠「把 47k 实体库接成反向决策回路」；L4 不是技术问题，是商业化问题；L5 不是本项目的目标。
