## 1. 一句话定位

**SwarmLabs Workbench = ScienceBuddy 的产品形态 × SwarmLabs 的验证核心 × 用户自选模型后端**

- **形态**：借鉴 ScienceBuddy 的交互式科研工作台（Chat + Trajectory + Compute）
- **核心**：SwarmLabs 独家的**可信验证层**（42 门禁 / 5 独立不变量 / 6 preflight / 82 场景基准 / 三维证据锚定 / GP+UQ）
- **后端**：**用户自选模型**（本地 Ollama / SenseNova / TypeSafe Jev / 用户自训小模型）——我们不养模型，只做验证层

## 4. 关键设计纪律（防坑）

### 纪律 1：LLM 只用于解释层，不参与验证判定

- **引擎计算**（GP+UQ / 门禁评估 / 锚点匹配 / UQ 校准）= **纯 Python**，不依赖 LLM
- **LLM 调用**（诊断失败原因 / 生成解释 / 建议下一步）= 可用 LLM，用户自选
- **原因**：不同模型输出质量差异大，如果 LLM 参与 V&V 判定，会污染验证层的核心资产

### 纪律 2：Harness 修改必须配对评测才接受

- 任何 harness 修改（新增/删除/修改门禁）都必须：
  1. 在 82 场景基准上跑一次
  2. 得分（V&V PASS 率 / REFUTED 精确率）必须 ≥ 当前版本
  3. 否则**拒绝修改**（保留原版本）
- **原因**：借鉴 ScienceBuddy 的 "配对评测 ΔS≥0" 接受规则，防止 harness 退化

### 纪律 3：Harness 版本化 + 可回滚

- 每次 harness 修改 = 一个版本（v1.0, v1.1, v1.2...）
- 每次发布记录：修改内容、评测分数、接受理由
- 支持一键回滚到任意历史版本

## 6. 与之前判断的调和

**旧判断**（memory）：ScienceHub 技能线停止追加投入——分发不改变替代性

**新判断（v2）**：
- **单纯的 MCP 上架** = 分发，不改变替代性（此判断不变，不再追加投资）
- **Workbench + Harness 自进化** = 产品形态，是"让替代性可感知、可验证、可迭代"，**改替代性**

**本质区别**：
| 路径 | 改替代性？ | 理由 |
|---|---|---|
| MCP 上架 | ❌ | 让用户找到我们，但不改引擎能力 |
| Workbench + Harness 自进化 | ✅ | 让验证层可自我修复 + 让用户用起来 + 反馈变迭代信号 |
| 模型训练 | ⚠️ 部分 | 我们自己训模型不改替代性；用户训模型 + 我们验证 = 改 |

## 7. 明确不做的（永久排除）

- **GPU 加速**：SwarmLabs 引擎是纯 Python，无 GPU 依赖是设计原则
- **单一厂商模型锁定**：用户自选，不绑定 OpenAI / Anthropic / 特定厂商
- **224 工具全量复刻**：分批扩展，不一口气做满（防止过度工程）
- **纯工具集成不带 harness**：所有工具都必须在 42 门禁下运行，不允许绕过验证层

## 9. 与 ScienceBuddy 的关系定位

**不是竞品，是上下游**：

| 维度 | ScienceBuddy | SwarmLabs Workbench |
|---|---|---|
| 定位 | 让 AI **做** 科研 | 让 AI **验证** 替代真实实验 |
| 输入 | 研究者问题 | ScienceBuddy 输出的假设 / 用户假设 |
| 输出 | 分析报告、工具轨迹 | V&V 报告、置信度、REFUTED 判定、3D 锚点 |
| 关系 | 上游（产出假设） | 下游（验证假设） |
| 类比 | Deep Research / ChatGPT for Science | Peer Review + Wet Lab 替代品 |

**关键洞察**：ScienceBuddy 越强，产出的假设越多、越多样 → **越需要 SwarmLabs 做验证层**。这是**正和**关系，不是竞争。
