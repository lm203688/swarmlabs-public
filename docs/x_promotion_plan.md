# 借鉴 X（Twitter）开源推荐算法做 SwarmLabs 推广

> 用户指令：「借鉴 X 平台的开源算法做推广」。
> 事实基础：X 于 2023-03-31 开源推荐算法（`twitter/the-algorithm` + `twitter/the-algorithm-ml`），三阶段管线已公开：
> **Candidate Sourcing（候选生成）→ Heavy Ranker（重排序）→ Heuristics & Filtering（启发式/过滤）**。
> 本文档**借鉴其设计哲学**做我们自己的推广策略与内容优先级，而非试图操控 X 平台本身（X 的最终排序不可控）。

---

## 1. X 开源算法骨架（公开事实，作为借鉴蓝本）

| 阶段 | 机制 | 可借鉴点 |
|------|------|----------|
| **候选生成** | ~1500 候选，约 50% 来自关注图（RealGraph 预测用户间互动概率），约 50% 来自关注图外（SimClusters 社区聚类 + 嵌入空间相似用户/内容） | ① **兴趣图/社区定向**：内容要绑到具体领域社区，而非泛科技通投；② 关注图 → 找 KOL/社群做冷启动 |
| **Heavy Ranker** | 神经网络（约 4800 万参数）用数千特征（用户/作者/推文特征 + 实时互动）预测正向互动（赞/转/评），排序候选 | ③ 用我们**自己的"重排序"**对内容队列排优先级：可信度 × 信息量 × 领域需求 |
| **启发式/过滤** | 作者多样性（避免同作者连发）、反馈疲劳（负反馈降权）、社交证明（被关注者互动过的才推）、内容平衡 | ④ 发布节律与负反馈闭环；⑤ 权威锚点建立社交证明 |

**关键认知**：X 奖励「相关 + 高互动 + 权威 + 不垃圾」的内容。我们控制不了 X 的排序，但可**让内容形态与目标社群匹配其偏好**，从而被其算法放大。

---

## 2. 三层落地映射

### Layer A — 兴趣图/社区定向（借 SimClusters / RealGraph）
- X 的 out-of-network 靠「社区聚类 + 相似用户」分发。我们的对应物就是 **10 已验证域 + 138 待接入域的 taxonomy**——它本身就是一张领域兴趣图。
- 每条内容必须**绑定一个具体域/场景**，例如：
  - 「用 GP 代理 + UQ 误差棒验证 Suzuki 偶联反应产率」→ `#ComputationalChemistry #OrganicChemistry`
  - 「主动学习把材料实验试错次数砍半」→ `#MaterialsScience #LabAutomation`
  - 「微生物 Monod 动力学用 Bayesian 优化收敛」→ `#SyntheticBiology #Bioprocess`
- 拒绝泛主题（"AI 加速科研"太宽，无法进入任何社区聚类）。这直接呼应 #21「围绕使用场景」与审计 L5（清理泛主题微站）。
- 关注图冷启动：先关注/互动 `ActiveLearning`/`BayesianOptimization`/`LabAutomation`/`MaterialsInformatics` 等社群的 KOL，借其关注图进入对应社区。

### Layer B — Heavy Ranker 式内容优先级（借 Heavy Ranker 的"多特征排序"思想）
- X 用数千特征排推文。我们跑**自己的内容重排序**，对 `seo_engine` 的内容队列打分发帖优先级：
  ```
  score = credibility × information_gain × domain_demand
  ```
  - `credibility`：该场景 rubric 满通过？覆盖率双侧达标？（只用诚实高可信结果做门面，Chem 5.7% 收敛中则降权但不屏蔽）
  - `information_gain`：**复用我们自己的 ActiveLearner「最大后验方差」准则**——挑"信息量最大"的验证结果来展示（自指闭环：用主动学习挑最该做的实验，也用主动学习挑最该推的内容）
  - `domain_demand`：该域社群规模/检索热度（用 GEO 已积累的可见性粗略代理）
- 这保证我们推的不是"最多"的内容，而是"最有信号 + 最可信"的内容——与竞品 Robin 只循环不量化误差棒形成差异。

### Layer C — 启发式/负反馈闭环（借 Heuristics & Filtering）
- **作者多样性**：每天最多发 1–2 条，跨域轮换，避免单域刷屏被 X 降权。
- **反馈疲劳**：监控 X 原生负信号（0 曝光/0 点击/被「Not Interested」）→ 该角度降权；复用 `growth_monitor` 的双轨归因。
- **社交证明**：先在与 KOL/论文作者的对话里建立互动，再发主帖；引用真实论文（我们的 `references` 字段天然提供 social proof）。
- **人工审批闸门**（agent-boost 原则：发布=不可逆）：`seo_engine` 用本地 Ollama 零成本生成 X 草稿 → **用户确认后发**，不自动群发。

## 3. 务实发布通路（前置阻塞项）

| 项 | 现状 | 阻塞 | 解法 |
|----|------|------|------|
| X 发布通路 | Connectors 全断（仅 `agent-mail` 连） | 无法自动发帖 | 需用户开 X 开发者账号/API，或人工在 X 客户端发（AI 备料、用户发，低摩擦） |
| 内容生产 | `seo_engine.py` 已能用本地 Ollama 零成本生成短文 | 无 | 复用：每篇绑 1 域 + 1 张 `validation-dashboard` 图 |
| 度量 | `growth_monitor` 已有 site_visitors/注册/实验提交 | 无 X 互动指标 | 增 X impression/click/link-click 字段，双轨归因（GEO + X），不编造假数据 |

## 4. 日级闭环（与现有飞轮咬合）

```
每日飞轮 run_day → 产出新验证点 / 新可信面
        ↓
seo_engine 生成"场景级"X 草稿（绑域 + 误差棒图，零成本）
        ↓
【人工闸门】用户确认 → X 发布
        ↓
growth_monitor 采集 X 互动 + 站点转化 → 双轨归因
        ↓
反馈回到 Layer B 重排序（高互动域加权，0 互动域降权）
```

---

## 5. 诚实边界（必须遵守）

- X 平台最终排序不可控；本方案只借鉴「设计哲学 + 内容/社群匹配」，不承诺曝光量。
- 内容所有 ground-truth 必须来自已发表基准/解析解（同 10 域 rigor），**不得对 Track B 的 155 启发式引擎称"已验证"**（审计 L1）。
- 真实外部用户≈0，X 推广成效需时间积累；短期只证可达性/合规，不证引用量。
- 不买粉、不刷互动——X 的 Trust & Safety 与反馈疲劳机制会惩罚，且违背项目诚实底线。

---

## 6. 立即可做的 3 件事（不等 X API）

1. **内容侧改造**：把 `seo_engine` 的 GEO 文章从"泛主题"重写为"场景级"（每篇绑 1 个已验证域 + 1 张误差棒图），与 Layer A 一致。
2. **社群清单**：整理 10 域对应的 X 社群/话题标签/KOL 清单（我可起草，用户校准）。
3. **人工发帖模板**：用 `seo_engine` 产出首批 5 条场景级草稿，等用户开 X 账号后直接发。

> 注：X 算法细节来自 2023-03 开源版本（`twitter/the-algorithm`），后续版本可能迭代；本方案借鉴的是其稳定的"候选生成→重排序→过滤"设计范式，与具体权重无关。
