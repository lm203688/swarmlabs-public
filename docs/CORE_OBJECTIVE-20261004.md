### 新增过程中发现并修掉的三个自身缺陷（如实记录）

1. **`dim` 字段类型错误导致场景「静默消失」**：
   初版把参数名列表塞进 `dim`，而 `report_generator._normalize` 会对
   `dim` 做 `int()` → TypeError 被 `except: pass` **静默吞掉** → 表现是
   「13 个新场景凭空消失、总数仍是 82」。且
   `paper_validation_loop` 与 `report_generator` 是**两条独立装配路径**，
   只改一处必然导致两套注册表漂移（正是该文件 docstring 里警告过的
   「三套注册表必然漂移」）。已在 selftest 加跨模块契约检查。

2. **含乘积项的函数不能独立设 bounds**：
   `neuro_lif_fi` 的 `drive = V_rest + R·I`，初版 `I≤200 nA × R≤100 MΩ`
   导致上界达 **20 V**，而阈值只有 50 mV → 99.9% 采样点落在饱和区
   → GP 看不到跃变 → 被诚实门禁判 **REFUTED**（r²=0.41）。
   这是**我的设计缺陷，不是方法的局限**。按乘积可达范围重设 bounds
   （`I≤10 nA × R≤5 MΩ` → drive 上界 -20 mV）后修复。
   **教训与 A14 的「跨数量级 bounds」同源：bounds 决定了 oracle 在哪里
   被采样。**

3. **零函数负对照不该占 benchmark 名额**：
   `fin_put_call_parity`（put-call parity 残差，理论恒为 0）进门禁后被判
   REFUTED（r²=-0.027）——这是**正确判定**（R² 对常数目标无意义），
   但它进 benchmark 会把「诚实判负」与「场景失败」混在一起，污染
   REFUTED 率。已移出，改作 selftest 断言（残差 < 1e-8）。

**结果：新增 13 个场景零 REFUTED**，账本 95/91-3-1-0，
唯一 REFUTED 仍是 `mol_suzuki_yield`（硬阻断）。

### 产品化的分界点：实验输出接口

§3.5 说「输出不是预测值，而是下一个最该做的实验 + 做完之后结论
会变成什么样」。此前三个零件都有、但**从未接在一起**：

| 零件 | 位置 | 状态 |
|---|---|---|
| `conclusion` | trust_surface 的 rmse/cov/cal | ✅ |
| `boundary` | `assess_applicability`（A14） | ✅ |
| `next_experiment` | `rank_next_experiments` | ✅ |
| **组合 + 让 expected_improvement 可证伪** | `engine/experiment_proposal.py` | ✅ **本轮补上** |

关键设计：不给「不可达标的场景」实验建议（那个模型结论不可信，
给建议是误导）；`expected_improvement` 写成可事后核对的断言，
累积 miss 率 ≥0.6 才算可信，否则建议下调 confidence。

**实测代价（不掩盖）**：全 82 场景「CI 半宽/值」中位 **22.03×**。
这不是 bug——conformal q 是保守分位数（实测 0.44~75.66），且
`std_out` 是测试集上 epistemic std 的均值。与 `coverage_ok=80/82`
不矛盾：coverage 问「95% 真值落在区间内」，区间**可以**宽而位置正确。
代价体现在 `sharpness` 门禁。

## 0. 一句话核心目标

**让虚拟实验成为「跨学科科研问题的硬验证输出」——用一个可复现的代理
模型 + 不确定性量化 + 实验闭环，把「我想验证一个科学假设」变成
「我拿到了一个带校准区间的可证伪结论，以及下一个最该做的实验」。**

### 1.2 三个致命缺口

**缺口 1：泛化能力证据 = 0**

现有全部 82 个场景的 train/test 都是**同一分布内**划分（LHS 采样后
随机切分）。这只能证明「代理模型能插值」，**不能证明「代理模型能外推」**。

而「能外推」才是科研场景的真实需求：一个微生物学家不会帮你采 30 个点
然后只在你采过的范围内预测。

**证据**：本次全量扫描 82 个场景，**无任何一个场景做跨场景/跨学科外推**。

**缺口 2：学科覆盖是「广度数字」而非「深度证据」**

16 个学科里 **10 个只有 1 个场景**：

| 只有 1 个场景的学科 | 场景 |
|---|---|
| neuroscience | `neuro_hh_spike_amplitude` |
| ecology | `eco_lv_peak_ratio` |
| finance | （1 个） |
| LLM | `llm_scaling` |
| energy | （1 个） |
| Heat Conduction | `pde_heat1d` |
| biology / Biology | 2 个 |
| Chemical / Chemistry / chemistry | 3 个 |

1 个场景的学科**在统计上无法支撑任何泛化结论**。这不是「覆盖了 16 个
学科」，这是「16 个学科各有一个样本」。

**缺口 3：场景性质是 benchmark 不是科研问题**

- 基础科学/机理（micro/mol/bio）：55 (67%)——**全挤在微生物**
- 工程基准（surrogate/opt/pde）：20 (24%)
- 其他：7

`opt_rastrigin2d` / `surrogate_branin` 这类场景证明的是「GP 实现正确」，
**不是「解决了某个科学问题」**。它们有科研价值（方法学标定），但
**不能支撑「SwarmLabs 能做科研」这个主张**。

## 2. 重新核定的核心目标

### 2.1 目标分层

```
L0  方法学可信     ← 已有（A1~A14 + 三通道 + 100% 溯源）
      ↓
L1  跨场景泛化     ← 缺失（泛化证据 = 0）★ 当前最大缺口
      ↓
L2  跨学科外推     ← 缺失（10 个学科各 1 场景）
      ↓
L3  实验闭环       ← 部分有（主动学习补点），未形成「实验是可验证输出」
      ↓
L4  科研假设驱动   ← 缺失（当前是「跑场景」，不是「验证假设」）
```

### 2.2 核心目标（一句话版 + 可验收版）

> **核心目标**：让 SwarmLabs 从「代理模型基准测试集」升级为
> **「跨学科科研问题的可证伪结论生成器」**。
>
> **验收标准**：给定一个**从未在任何文献中被代理建模过**的跨学科科学问题，
> SwarmLabs 能在 **≤ 20 次虚拟实验**内给出：
> 1. 一个带 95% 校准区间的定量结论
> 2. 一个明确的「当前结论在哪些条件下不成立」（适用域边界）
> 3. 一个可执行的下一步实验建议，且该建议被采纳后能提升结论的校准质量

### 2.3 准入判据（沿用项目既有原则，不新增）

**是否让虚拟实验在无真实实验/网络/设备下更可替代？**

具体化为 5 条可判定的准入问题（任一为「否」则该场景不该进体系）：

| # | 准入问题 | 当前是否满足 |
|---|---|---|
| 1 | 这个问题的答案是**可证伪的**（有明确的成功/失败判据）？ | 部分（benchmark 是的，科研问题待审） |
| 2 | 有**独立于本项目**的真值来源（文献/实验）？ | ✅ 82/82 有溯源 |
| 3 | 不做这个场景，研究者会**真的卡住**？ | ❌ opt_rastrigin2d 不会 |
| 4 | 结果能**跨场景复用**（泛化到别的领域）？ | ❌ 未证明 |
| 5 | 失败的代价是**可承受**的（不是临床/安全攸关）？ | ✅ 全部是 |

## 3. 应用场景重新梳理

### 3.1 从「场景库」到「科研场景体系」

现有结构是**扁平的 82 个场景**。新体系分三层，每层有不同职责：

```
┌─────────────────────────────────────────────────────────────┐
│ 第 3 层：科研场景（Research Scenarios）                       │
│   跨学科、真实科学问题、有可证伪结论                           │
│   职责：证明「这套方法能做科研」                                 │
├─────────────────────────────────────────────────────────────┤
│ 第 2 层：泛化基准（Generalization Benchmarks）  ★ 新增        │
│   留一学科外推 / 留一域外推 / 参数外推                          │
│   职责：证明「这套方法能外推」——**当前完全缺失**                 │
├─────────────────────────────────────────────────────────────┤
│ 第 1 层：方法学标定（Methodological Calibration）             │
│   现有的 surrogate/opt/pde + 新增的跨数量级/多模态边界         │
│   职责：证明「实现是对的 + 知道边界在哪」                        │
└─────────────────────────────────────────────────────────────┘
```

**关键洞察**：第 1 层已有 20 个工程基准，**它们的作用是标定方法，
不是证明科研能力**。之前把它们和科研场景混在一起算「82 个场景」，
导致分子失真（67% 微生物）。

### 3.2 科研场景的准入标准（比 rubric 严）

一个场景要进第 3 层，必须满足：

| # | 标准 | 可判定判据 |
|---|---|---|
| R1 | **跨学科**：至少涉及 2 个学科 | 场景声明 `disciplines: [primary, secondary]` |
| R2 | **有真实未解问题**：文献里有争议或未测量 | 需人工审核 + 文献引用 |
| R3 | **有独立真值**：至少 3 个已发表数据点 | `anchor_count >= 3`（不是 1 个） |
| R4 | **可证伪**：明确写出「什么结果会证伪这个结论」 | `falsification_criterion` 字段非空 |
| R5 | **可外推**：能说清「在哪些邻近领域也成立」 | `transfer_hypothesis` 非空 |
| R6 | **非 benchmark**：不是纯数值优化题 | 人工审核 |

**对照现有 82 个场景**：能同时满足 R1~R6 的，我判断**不超过 5 个**
（`micro_lag_ecoli`（生物+化学）、`micro_chemostat_*`（生物+化工）、
`mol_*`（化学+材料）、`eco_lv_peak_ratio`（生态+数学）等）。

**这个数字很小是正常的**——真正的科研场景本来就少。
把它做大只能靠降低标准，那会变成 benchmark 灌水。

### 3.3 建议扩展的跨学科方向（按「泛化价值」排序）

排序依据：**该方向的结论能否迁移到已有领域**（迁移性越高，
新增一个场景的边际价值越大）。

| 优先级 | 方向 | 跨学科组合 | 为什么泛化价值高 |
|---|---|---|---|
| **P0** | **反应-扩散-输运耦合** | 化学 + 物理 + 生物 | 形态发生/生态/催化/肿瘤生长**同一个 PDE 骨架**。微生物场景已隐含这个结构，只是没显式化 |
| **P0** | **稳定性与相变** | 物理 + 材料 + 化学 | Hopf 分岔已经在 micro_chemostat 里出现。**chaos/monodromy** 是跨领域的通用语言 |
| **P1** | **群体动力学与流行病学** | 生物 + 统计 + 网络 | SIR/SEIR 的泛化能力直接可迁移到微生物竞争（`micro_competition_*` 已有雏形） |
| **P1** | **信息-动力学耦合** | 神经科学 + 统计物理 | Hopfield/HH 已有 1 个场景。跨领域迁移到生态（个体行为→群体模式） |
| **P2** | **代谢网络与约束优化** | 化学 + 工业工程 | FBA（flux balance analysis）可直接迁移到发酵控制 |
| **P2** | **多尺度耦合（分子→宏观）** | 化学 + 材料 + 力学 | 跨尺度验证是当前竞品的空白区 |

**第一个要建的 P0 方向：反应-扩散-输运耦合。**

理由：SwarmLabs 已有 55 个微生物场景，它们底层**全都是 ODE**。
把其中部分升级为 **PDE（含扩散/输运项）**，就得到：
- 同一个代码骨架覆盖微生物（1D 空间）+ 生态（2D 空间）+ 肿瘤 + 催化
- 空间维度引入**新的科学问题**（形态发生 Turing 图案、斑图稳定性）
- 现有 GP 代理 + 适用域检测（A14）方法**直接适用**

### 3.4 泛化能力的三级验收（这是「硬技术门槛」的核心）

**泛化**不能靠嘴说，必须可测。定义三级：

| 级别 | 名称 | 定义 | 判据 | 当前 |
|---|---|---|---|---|
| **G1** | 参数外推 | 在 `[a,b]` 采样训练，预测 `[b, 1.5b]` | 外推段 rel rmse ≤ 内插段 × 2 | ❌ 未测 |
| **G2** | 留一维外推 | 2D 场景训练时剔除一个维度，测试该维度 | 留出维度 rel ≤ 内插 × 3 | ❌ 未测 |
| **G3** | **留一学科外推** | 训练时**完全剔除**某学科所有场景，测试该学科 | 留出学科 rubric 达标率 ≥ 50% | ❌ 未测 |

**G3 是关键**。它是「这套方法能跨学科用」的唯一硬证据。
如果 G3 做不到，那 67% 微生物集中就是**方法的本质局限**，
而不是数据收集问题——**必须诚实说出来**。

### 3.5 实验作为「可验证输出」

用户诉求：「让实验成为验证所有事情可能性的一个硬技术可验证的输出」。

理解这句话的正确形式：

> **实验（真实或虚拟）不是一个「验证环节」，而是整个系统的输出类型。**
> SwarmLabs 的输出不是「预测值」，而是**「下一个最该做的实验 + 做完
> 之后结论会变成什么样」**。

形式化为一个可验收的接口：

```
hypothesis → SwarmLabs → {
    conclusion: {value, ci95, applicable_range},   # 带校准的结论
    boundary: {valid_when, fails_when},            # 适用域边界（A14）
    next_experiment: {                             # ★ 实验作为输出
        priority: 0-1,                             # 预期信息增益
        params: [...],                             # 具体参数建议
        expected_improvement: {                    # 做了之后会怎样
            rmse_rel: 0.35 → 0.12,
            coverage: 0.87 → 0.94,
        },
        falsification_test: "若实验后 <条件>，则该假设被证伪"
    }
}
```

**这个接口已经有两个零件**：
- `conclusion` + `boundary`：已有（`assess_applicability`，A14）
- `next_experiment`：已有雏形（`AcquisitionVolume` / `ActiveLearner`）
  但**从未与前两者组合成一个可验收的整体**。

**缺口：把三者接起来，并让 `expected_improvement` 可被证伪。**
即：实验做完之后，系统必须能说「我预测 rmse 会从 0.35 降到 0.12」，
而这个预测本身也要被检验。**这才叫硬技术可验证。**

## 4. 竞品对照：我们真正的差异化在哪

| 能力 | Google Co-Scientist | Anthropic 950 agents | 传统 V&V（SigmaFit 等） | **SwarmLabs** |
|---|---|---|---|---|
| 自动发现假设 | ✅ | ✅（20万→1个发现） | ❌ | 部分（SINDy） |
| **可复现性** | ❌ 未公开 | ❌ **10 次重跑 0/10 复现** | ✅ | ✅ 种子固定 |
| **不确定性校准** | ❌ | ❌ | ⚠️ 只有统计检验 | ✅ **conformal + 双侧 coverage** |
| **形式化验证** | ❌ | ❌ | ❌ | ✅ **Python + Z3 + Lean 三通道** |
| **失效模式公开** | ❌ | ❌ | ❌ | ✅ **A1~A14** |
| **跨学科泛化证据** | ❌ | ❌ | ❌ | ❌ **（G3 未测，最大缺口）** |
| 实验闭环 | ❌ | ❌ | ❌ | ⚠️ 雏形（未接结论） |

**结论**：我们的差异化**不在「能发现什么」**（Google/Anthropic 强得多），
而在**「能证明发现是对的，以及在什么条件下不对」**。

但**G3（跨学科泛化）未测**是这个差异化叙事最大的漏洞——
我们说「我们是可信的验证层」，但还没有证明「我们能验证**陌生领域**
的东西」。补上 G3 是当前最高杠杆的一件事。

## 6. 诚实声明（必须一起说）

**这份目标重新核定后，最刺眼的事实是：**

1. **我们还没有证明「能外推」**。82 个场景全部是同分布内插值。
2. **跨学科是数字覆盖不是深度覆盖**。16 学科里 10 个只有 1 个场景。
3. **科研场景（能同时满足 R1~R6 的）不超过 5 个**。现有的 82 个里
   绝大多数是方法学标定 + 单一领域深耕。
4. **G3 如果做出来结果是 0%，也是有效结论**——那时应该把项目定位
   从「跨学科验证层」收窄为「生物过程可信代理层」，并把资源集中到
   那个真正做得住的方向。**收缩定位不丢人，拿未验证的主张去融资才丢人。**

## 8. G3=0% 实测结论与定位收窄（2026-10-10 更新）

### 8.1 G3 实测：0/14 学科（0%）

G3（留一学科外推）已于 2026-10-05 完成实测：

| 度量 | 数值 | 说明 |
|---|---|---|
| G3 pass rate | **0.0%** (0/14) | 无一学科跨学科泛化达标 |
| 量纲修复后最差 | 微生物 mean rel=168.79 | 远超 0.15 判据 |
| 最佳学科 | surrogate modeling mean rel=1.50 | 仍不达标 |
| 跨学科语义对齐 | G3 仍 0% | PCA + MMD 对齐层未能拯救 |

**G3=0% 是技术架构限制，不是工程问题**：GP 只学 (x,y) 数值对，无跨学科语义理解能力。

### 8.2 定位收窄

核心目标从「跨学科科研问题的可证伪结论生成器」收窄为：

> **「单学科内科研过程的可信代理验证层」**——在已知设计域内，
> 用代理模型 + 不确定性量化 + 实验闭环，把「我想验证一个科学假设」变成
> 「我拿到了一个带校准区间的可证伪结论，以及下一个最该做的实验」。

### 8.3 新定位的硬边界

| 维度 | 当前状态 | 能否宣称 |
|---|---|---|
| 单学科内插值验证 | G1=27.8%, G2=80.0% | ✅ 可以 |
| 跨学科外推 | G3=0% | ❌ 不宣称 |
| 设计域外推 | A15 外推不可达 | ❌ 不宣称 |
| 机理泛化 | 无数值证据 | ❌ 不宣称 |

详细分析见 `docs/axiom-audit-g3-zero.md`。

### 8.4 差异化重新定义

收缩后，SwarmLabs 的差异化不在「能做更多学科」，而在：

1. **诚实的适用域边界**（A14 + OOD 守卫 + 拒答机制）
2. **可审计的验证流程**（A1~A17 失效模式 + 17 复现脚本）
3. **单学科内的实验闭环**（conclusion + boundary + next_experiment 三件套）
4. **形式化验证**（Python + Z3 + Lean 三通道）

**在 AI4S 领域，诚实公开 0% 比假装「有潜力」更有价值。**
