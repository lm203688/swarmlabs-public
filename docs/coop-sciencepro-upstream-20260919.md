我们的位置。

> 创新评价「**评价效果与专家结论匹配度达到 80% 以上**」

两者极易被混为一谈，对外表述时必须点明区别，否则我们会显得像在复述它已有的东西。

## 2. 为什么"它是上游"在结构上成立，而不是话术

看它自己的免责声明（每个版本都出现）：

> "最终评价与研究决策仍由科研人员和评审专家负责。"

这不是谦辞。这是**平台商业模式决定的必然**：卖能力的人不能同时当裁判，因为
一旦它对某个方向说"不许做"，它就要为错杀承担责任。

于是分工是**结构性的**，不是我们主动让出来的：

```
SciencePro（上游）                 SwarmLabs（下游）
  生成候选方案 / 预测                 对这些产出做独立裁决
  ↑ 越强 → 候选越多 →                  ↑ 不可替代性越高
  多智能体出结构化报告                  fail-closed：够不到证据就拒绝放行
  不做最终判断                          只做最终判断
```

**它成功 = 我们的输入变多。** 反过来，如果它开始做裁决，它会伤自己的销售话术
（"我们能替你决定"和"最终由你负责"不能同时说）。这是它**不会来抢**的位置。

## 5. 通路 D 必须否掉：不存在"拿它的数据补我们的库"

用户提出的假设之一是"利用它的数据量来完善自己的项目"。**这条不成立，必须直说。**

| 障碍 | 事实 |
|---|---|
| 无开放数据 API | 全站未见任何面向第三方的检索/导出 API 文档；能力只以**平台内对话/Skill**形态暴露 |
| 无批量导出 | 90PB 数据在其内网；论文/专利多为**第三方版权源**（2.7 亿条是聚合检索，不是自有可再分发资产） |
| 合规与 ToS | 抓取聚合库 = 绕过其访问控制 + 上游版权方风险，且违反"作品须原创、不得搬运"的平台规范精神 |
| 即便成功也无效 | 我们 47,566 实体 vs 它 2.7 亿：**数量级差 5700×**，比拼数量是一场必输的消耗战 |

**能做的只有运行时借用**：在平台内的 Skill/智能体里调用它的检索，把检索结果交给
我们的门禁做可信性裁决。数据**不落地到我们的库**——这也顺带避免了"我们的护城河
是别人的数据集"这种最脆弱的战略姿态。

我们真正的护城河是**判定权 + 诚实的不确定度**，不是实体条数。

## 6. "平台级"与"玩具级"的六个判据（本次交付物就在这六个格子里）

这是用户问题的正面回答：不是加功能，而是**把证据做成可移交的资产**。

| # | 判据 | 玩具级 | 平台级 | 我方现状 |
|---|---|---|---|---|
| 1 | **可归档** | 跑完输出一个数字，散落在会话里 | 单目录/单 zip，含全部证据 | ✅ `dist/vvpkg-2026-09-19/` + `.zip`（2.9MB） |
| 2 | **可移交** | 结论离开你就不成立 | 第三方无需你的账号/仓库/环境即可读 | ✅ README + manifest + CHECKS，全文自解释 |
| 3 | **可复验** | 复验=再信你一次 | 校验和 + 复跑命令 + 退出码语义 | ✅ `verify` → `PACKAGE_INTACT`(0)/`TAMPERED`(2)，**已实测篡改可捕获** |
| 4 | **可追溯** | 不知道是哪版算的 | 引擎/oracle 源码指纹随结论走 | ✅ `git_commit` + `all_digest` + `core` 逐文件 sha256 |
| 5 | **有标准** | 自定阈值，无从对照 | 挂到公开标准上 | ✅ `ASME V&V 10-2019 / FDA CM&S report outline` |
| 6 | **诚实边界写进产物** | 边界在 PPT 里 | 边界在数据里，跟着包走 | ✅ `honest_boundaries` 字段 + README 章节 |

### 6.1 本次交付：V&V 归档包

新增 `engine/vv_package.py`（纯标准库）+ `scripts/build_vv_package.py`。

**实测结果**：

```
BUILT   dist/vvpkg-2026-09-19
  package_id   : vvpkg-170dd6f4895f
  scenarios    : 62
  verdicts     : {"PASS": 62}
  blocked      : 0
  files        : 253 (sha256)
  ground truth : committed only (y_sha256)
  engine commit: 1de10d634d2274ff4d8866ab899ac515d353c8a4
  zip          : dist/vvpkg-2026-09-19.zip (3027734 bytes)

验证完整性 → exit 0, PACKAGE_INTACT
篡改一个字节 → exit 2, files_mismatched: ["scenarios/bio_logistic.json"]
零依赖自检   → STDLIB_ONLY_OK（numpy/scipy/pandas/torch 全部未引入）
```

三个刻意的设计决策：

1. **留出集真值默认不入包**，只放 `x_sha256` / `y_sha256` 承诺。
   把 `y` 放进可自由移交的包 = 泄漏评分标准 + 给下次自证留作弊面。
   内部完整归档需显式 `--include-ground-truth`，且 manifest 会标记
   `contains_ground_truth: true`。
2. **复验器零依赖**。若复验器偷偷依赖 numpy，"第三方可独立复验"就只是把信任对象
   从"我们的结论"换成了"我们的环境"。本次实测 `STDLIB_ONLY_OK`。
3. **不重算判定**。包只搬运引擎已签发的 verdict/gate，并标注阈值来源，绝不自行
   发明阈值——那会制造第二套口径。

对照它的 `Projects`：它以课题为单位归档"文件资料、Skills、工具连接、参数配置"。
我们有同样的容器，但多了 **可追溯（3/4）、可复验（5）** 这两层——而这两层恰好是
"归档"与"证据"的区别。
