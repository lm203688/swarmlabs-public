1. End-to-end autonomous loop goal in → experiment design → model execution → result verification → knowledge deposit

PlannerAgent
Understands the goal, decomposes it into an executable experiment plan JSON (candidate engines, parameter space, metrics, budget). Read-only, does not execute.
ExecutorAgent
Runs computations against real physics/math models, collecting execution evidence (trace + latency). Read-only computation.
VerifierAgent
Checks result soundness, uses active learning (expected information gain) to decide the next sampling, and deposits an auditable report.
Knowledge deposit
Report + trace written to a reusable knowledge base, fed back to the Planner to form an iterative loop.
The three agents have mutually exclusive responsibilities (plan does not execute / execute does not judge / verify does not compute). All high-risk write operations go through approval and rollback — matching the "permission boundaries + safe & auditable" requirement for trustworthy agents.

2. Real verification evidence 8 cross-discipline scenarios run daily; error bars are the hard metric of "mirroring reality"

Verification loop (real AgentLoop implementation)

  • Collect: real paper/benchmark data as ground-truth
  • Analyze: GP surrogate + UQ quantification (rmse / 95% CI coverage / calibration error)
  • Evaluate: maturity ranking (converged / converging / needs data)
  • Optimize: active-learning point addition → more accurate next round

Reusable skills (two layers, self-describing)

  • 6 orchestration-layer skills (the agentteams/ package): scenario.catalog · virtual_experiment.validate · active_learning.rank_candidates · uq.calibration_report · experiment.apply_correction · report.render
  • 4 MCP-layer skills (open-source engine-kit): PhysicsPredict · ExperimentDesign · ActiveLearning · ReportGeneration
  • Each skill carries 8 self-describing fields: purpose / inputs / outputs / preconditions / dependencies / side-effects & scope / risks / failure handling
  • The list is exported from code via --skills, so docs never drift

The open agent runtime package (agentteams/) runs today. Zero dependencies (numpy + PyYAML), runs offline, no API key required. The four snippets below are real run excerpts.

The Verifier flags the point to add, but the write is gated — the task degrades to partial instead of crashing: autonomous but never out of control.

② Four-stage audit chain after approval

approval | verifier | allow
write    | verifier | snapshot | files:1
write    | verifier | executed |
   scenario: microbio_monod
   added: 1  rmse_after: 0.008
Approve first, snapshot next, then execute. The order is guaranteed by code; skipping the snapshot makes the write impossible.

③ Rollback is physically verifiable

knowledge-base points
  microbio_monod       11 → 10

The added data point is fully undone; the knowledge base returns to its pre-write state.

④ Flywheel self-drives: decides what to do

request specified no scenario →

  microbio_monod       rel= 5.3%
The Planner reads the previous flywheel state, auto-prioritizing the scenario with the larger error. The AgentLoop's Optimize→Collect closes across processes and days.
Honest migration estimate: core/runtime.py abstracts the runtime as an interface, with LocalRuntime and AgentTeamsRuntime side by side. Moving to a real agent runtime needs only two methods (_submit/_poll, ~50–80 lines of SDK glue); agent logic, skills, policies, and traces stay unchanged. The AgentTeamsRuntime is currently explicitly not wired in — we do not claim to run on a proprietary platform.
