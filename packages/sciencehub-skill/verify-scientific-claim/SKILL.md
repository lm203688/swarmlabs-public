# 科研结论裁决器（Verification Gate）

## 这个技能解决什么问题

AI4S 流程里最常见的假安全是：**模型给自己的结论打分**。智能体跑完一个仿真、
拟合出一条曲线、报出「R²=0.99」，然后说「已验证」。这句话在结构上是无意义的
——它只说明模型和自己算的数一致，不说明那个数对。

本技能把「谁说了算」从执行者手里拿走：它查询一个**你不控制、也不属于本次
执行**的门禁服务，因此它给出的答案可以是「**不行**」。

> 核心区分，也是本技能存在的理由：
> **可复现 ≠ 正确**。一个完全可复现的实验可以完全错。

## 何时必须激活（激活条件）

满足任一条即应激活：

- 用户要采用一个**数值结论**去驱动下一步（写进申报书、开实验、下结论）；
- 结论来自 LLM / 智能体 / 脚本，且**由产生它的一方自己声称已验证**；
- 用户问「这个数能不能信」「和文献一致吗」；
- 需要把「验证」变成一个**能拦住流程**的动作（CI 红、智能体停下）。

## 不激活的情形（避免误触发）

- 纯文献检索、纯文本润色、纯图表美化——本技能不评价「写得对不对」；
- 用户只是想看我们已公开的判定结果、不做新预测 → 用 `check` 而不是 `verify`
  （见下），且应说明这是**查询**而非裁决。

## 两个不同问题，不要混用

| 问题 | 命令 | 真值在哪 |
|---|---|---|
| 场景 X 的**当前信任状态**是什么？ | `check X` | 已发布门禁账本（静态） |
| **我**在这个留出集上的预测对不对？ | `verify X --pred p.json` | 留出集真值由服务方持有 |

`check` 回答「这个场景的代理模型本身是否可信」；
`verify` 回答「**你**错了」。只有第二个是对智能体的裁决。

## 执行步骤（固定路径，不要自行发挥）

前置：**零依赖**，Python 3.8+ 标准库即可，无需 numpy、无需 API key。

```bash
# 0. 自检（会真实访问服务，不是单测）
cd <本技能目录> && python scripts/vv_gate.py selftest

# 1. 静态查询：这个场景的判定与门禁
python scripts/vv_gate.py check microbio_monod

# 2. 生成待填预测模板（先看要提交什么形状）
python scripts/vv_gate.py template microbio_monod -o preds.json
#    → 填写 y_pred（可选 y_std = 你的 1σ）

# 3. 裁决
python scripts/vv_gate.py verify microbio_monod --pred preds.json
```

**不要**自己写脚本复算 R²、不要重新采样 `x`、不要修改阈值。阈值不在本技能里，
也不在客户端里——它们由服务端从单一真源导出（见
`references/gate-semantics.md` 第 5 条）。

## 退出码就是结论（不要翻译成别的话）

| 退出码 | 门禁 | 含义 | 你应该做什么 |
|---|---|---|---|
| `0` | PROCEED | 结论放行 | 可继续，但仍须披露下面的边界 |
| `3` | PROCEED_WITH_HUMAN_CHECK | 需人工签字 | 停下来找人确认，不要自动通过 |
| `2` | **BLOCK_AUTONOMOUS_ACTION** | **必须中止自主动作** | 停止流程并报告为什么被拒 |
| `4` | — | **够不到门禁**（网络/边缘失败） | 没有产生判定；重试或告警，**不得**当成通过 |
| `1` | — | 本地调用错误（JSON 坏、模板未填、非 JSON 回复） | 修输入 |

`2` 与 `4` 必须分开：`4` 是「没人裁决」，`2` 是「有人裁决说不行」。把两者合并且
当成失败，会让运维分不清「修网络」和「停下工作」；当成成功，则等于在无人裁决时
静默放行。

## 自由度与边界（本技能刻意收紧的部分）

- **必须**调用 `scripts/vv_gate.py`，不得用其他方式自行实现判定；
- **必须**原样报告退出码语义，不得把 `4` 说成「服务有问题所以先继续」；
- **不得**在未经用户知情的情况下把留出集真值当作可索取的资源——它不是；
- **不得**声称本技能验证了物理规律（见下）。

## 本技能**不能**做什么（对外表述时必须带上）

- 它**不验证物理**。它验证的是「预测对留出集 oracle 的忠实度」，并交叉核对
  文献区间。如果 oracle 本身错了，`PASS` 只意味着「忠于这个 oracle」。
  第二证据链（湿实验锚点）存在的唯一目的就是抓这种情况，而且它**确实**会
  真的报出 `CONTRADICTED` / `UNANCHORED`。
- 它**不覆盖全部场景**的锚点链。大多数场景没有可对照的物理量，那些被记为
  `UNANCHORED`，**不是**记为通过。
- 它**只评已发布的留出集**，不接受任意网格提交——这正是它能当门禁而不能当
  通用打分服务的原因。
- 当前基线的阻断数为 **0**。不要引用一个非零阻断数来证明门禁有效；
  一个从未开过火的门禁，只是你还没见过它的牙。

## 可归档证据包（把一次判定变成可移交资产）

裁决之外，本项目还提供**归档包**：把某次判定连同阈值来源、引擎/留出集指纹、
双证据链快照一起打包，第三方无需我们的环境即可核对完整性。

留出集真值**默认不入包**（会泄漏评分标准），包内只放 `y_sha256` 承诺。
涉及「把结论提交给别人审」的场景时，向用户说明这一点，并给出
`python scripts/build_vv_package.py verify <dir>` 的复验方式。
