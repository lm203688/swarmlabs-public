# 归档包与溯源（package-and-provenance）

本文件解释两件事：**一次判定如何变成可移交的证据**，以及**你怎么知道这套判定
对应的是哪一版引擎**。两者都是"可信"这个词里最容易被跳过、却最致命的部分。

## 一、为什么需要归档包

判定结论本身是一小段文本（`PASS` / 一个 R²）。把这段文本发给第三方时，你同时
隐去了它成立的全部条件：

- 是在**哪一版**引擎上算的？
- 对**哪一条**留出集？谁改过它没有？
- 阈值来自哪里？是谁说了算？
- 第二证据链当时是什么结论？

缺了这些，第三方唯一能做的动作是**信任你**——而这恰好是本项目声称要消除的东西。

归档包（V&V package）就是把「结论 + 使它可以被复核的最小事实集」捆在一起。

## 二、包内结构

| 路径 | 内容 |
|---|---|
| `manifest.json` | 机器读：策略、源码指纹、逐文件 sha256、复验入口 |
| `policy.json` | 阈值，从**唯一真源**导出（不是本地的第二份） |
| `standard.json` | 本次判定所依据的 V&V 标准与账本元信息 |
| `scenarios/<key>.json` | 单场景：verdict / gate / 不确定度 / **留出集承诺** |
| `evidence/wet_lab_anchors.json` | **第二、独立**证据链的快照 |
| `CHECKS.txt` | 人肉可读的校验和清单 |
| `README.md` | 人读：包含什么、不含什么、怎么复验 |

## 三、留出集真值**默认不入包**

这是刻意的设计，不是遗漏。

留出集是评分依据。把 `y` 放进一个可自由移交的包里，等于把答案卷一起发出去：
下一次"自证"就有了作弊面，而且**你无法证明没有发生**。

所以包内只放**承诺**：

```json
"heldout": {
  "n_test": 40,
  "test_seed": 991,
  "x_sha256": "…",
  "y_sha256": "…"
}
```

哈希按「键排序、无多余空白」的规范化 JSON 计算，因此换平台、换换行、换键序
都得到同一个值——**你拿自己那份数据能复算出同一个承诺**，从而确认「用的就是
这条留出集、且事后没被改过」，但拿不到答案。

内部完整归档可显式开 `--include-ground-truth`，此时 `manifest.json` 会标注
`"contains_ground_truth": true`，包不再适合对外移交。

## 四、怎么复验（两步，语义不同）

```bash
# 第 1 步｜完整性：包在生成之后有没有被改动？——离线，零依赖
python scripts/build_vv_package.py verify <dir>
# exit 0 = PACKAGE_INTACT ｜ exit 2 = PACKAGE_TAMPERED

# 第 2 步｜裁决：一个新的预测能不能过留出集？——需要联网
python scripts/vv_gate.py verify <key> --pred preds.json
# exit 0 PROCEED ｜ 2 BLOCK ｜ 3 HUMAN ｜ 4 够不到（无判定）
```

**第 1 步不等于第 2 步。** 完整性通过只说明文件没被动过，**不说明判定是对的**
——两者混淆正是"可复现 ≠ 正确"的另一种形态。工具的输出里也写了这句
（`note` 字段），因为它必须跟着数据走，而不是只写在文档里。

## 五、溯源字段怎么读

`manifest.json` 的 `provenance` 与 `policy_source`：

| 字段 | 含义 | 为什么重要 |
|---|---|---|
| `engine.git_commit` | 引擎源码的提交 | 判定钉死在某版代码上 |
| `engine.all_digest` | `engine/` 全部 .py 的联合摘要 | **任何**改动都会改变它 |
| `engine.core` | 判定相关核心模块逐个 sha256 | 出问题时能定位到具体文件 |
| `oracle.digest` | 场景真值函数（oracle）的指纹 | R²=1.0 只证明"忠于 oracle"，所以要能查"对哪版 oracle" |
| `policy_source` | 阈值出处 | 防止线上判定与报告判定各用一套数 |

如果 `all_digest` 与当前引擎不一致，含义不是"结论是错的"，而是
**"这个结论还没有针对当前引擎重算过"**——这是一个应当被显式处理的状态，
而不是默认沿用。

## 六、边界（对外表述时必须带上）

- `PASS` 只表示**忠于 oracle**；oracle 错了，`PASS` 仍然是错的。
- 大多数场景没有湿实验对照，记为 `UNANCHORED`，**不是**通过。
- 当前基线阻断数为 **0**；不要用非零阻断数证明门禁有效。
- 归档包不评价"研究想法好不好"——它只裁决**数值结论能不能被采用**。
